# 第 4 章：脚本生命周期与节点引用

## 这一章解决什么问题

脚本挂到节点上之后，Godot 会在固定的时刻调用几个函数。这一章分清两件已经在用的事：开场时做一次的准备，以及每一帧都发生的变化。同时看见脚本怎样按名字拿到自己的子节点。

## 先看哪棵场景树

场景是 `scenes/life.tscn`。没有从别的场景实例化进来的节点。

- `Life`：根节点，类型是 `Node2D`，挂着 `scripts/life.gd`
- `Dot`：`Life` 的子节点，红色方块，会从左向右移动
- `UI/Title`：屏幕上方的英文 `Chapter 4`

脚本第一行是 `extends Node2D`。根节点也必须是 `Node2D`。类型对不上，这份脚本就不能挂在那个节点上。

## 代码在做什么

看 `scripts/life.gd` 里这两行：

- `@onready var title: Label = $UI/Title` 对应场景里的 `UI/Title`
- `@onready var dot: Polygon2D = $Dot` 对应场景里的 `Dot`

`$` 后面是从当前节点出发的路径。`@onready` 表示等子节点都进了场景树再去找，这个查找发生在 `_ready` 函数体之前，并且只找一次。

`_ready` 只在开场运行一次。它打印取到的节点名字 `Title`。节点是空的就 `push_error`，避免后面把空节点当成找到了。

`_process` 在每一帧运行。`delta` 是离上一帧过了多少秒。方块的横坐标按这个时间往右加，超过 `1100` 就回到 `180`。它只改显示位置，所以放在 `_process`。要和碰撞体一起移动时，才改放到 `_physics_process`，那是第 9 章的内容。

## 建议改一处

把 `SLIDE_SPEED` 从 `120.0` 改成 `400.0`，保存后再运行。方块横向移动明显变快。终端里那句「取到子节点 Title」仍然只出现一次。

## 自测

通过的标准有两条：

1. 方块跟着时间移动的那段代码在 `_process`。如果这段代码改成和地面发生碰撞，就应该放到 `_physics_process`。
2. `@onready var title` 那一行对应场景节点 `UI/Title`，`@onready var dot` 对应 `Dot`。

## 本章停在哪里

不使用信号把节点拆开，那是第 5 章。不写走路、重力和碰撞，也不做状态机。
