# 第 4 章：脚本生命周期与节点引用

- 状态：未开始
- 前置：第 2、3 章

## 学完应该能做什么

把脚本挂到节点上，说清 `_ready`、`_process`、`_physics_process` 大概何时运行，并用 `@onready` 拿到子节点。

## 本章要认识的内容

- `extends` 必须和挂载的节点类型匹配
- `_ready` 适合做开场时的一次性准备
- 每帧逻辑和物理帧逻辑的使用场合
- `$节点名` 和 `@onready` 类型化引用
- 节点还不存在时会怎样，以及用 `push_error` 把路径错误说清楚

## 本章不展开

- 用信号解耦（第 5 章）
- 具体的移动和碰撞算法（第 9、10 章）
- 状态机

## 以后生成示例时要覆盖的点

- 场景里有父子节点，脚本在 `_ready` 里取到子节点并打印它的名字
- 同一个脚本在 `_process` 里改变一个看得见的属性（例如位置或透明度），用来感受「每帧都在发生」
- README 写明故意改错路径时输出面板应出现的错误

## 自测

能指出一段「跟着时间变」的代码该放进哪个回调，以及 `@onready` 那一行对应场景里的哪个节点。
