## 学完应该能做什么

把少量进度和设置写到本机用户目录，关闭游戏再打开后还能读回来。说清 `res://` 和 `user://` 的差别。

## 本章要认识的内容

- `res://` 是项目资源，发布后通常不能当存档去写
- `user://` 是这台机器上该游戏的用户数据
- 用 `ConfigFile` 或 JSON 保存少量键值。本章选一种作为主路径，另一种只作对照
- 存什么：例如最高分、音量、是否看过教程。不在这一章设计复杂世界快照

## 本章不展开

- 加密、云存档、多槽位的完整界面
- 把整个场景树序列化
- 版本迁移框架。可以在注释里留一句「以后字段变化时要能认出旧存档」

## 以后生成示例时要覆盖的点

- 一次运行里改变一个数值并保存
- 重新运行示例后，这个数值还在
- 存档文件路径写在 README 里，并说明它不在 `res://` 下

## 自测

删掉用户目录里的那个存档文件后，再运行会回到默认值，而项目资源没有被改写。
