# 注释

注释用简体中文。目的是让以后的自己和 AI 能看出这段代码为什么存在、要挂在什么节点上。注释不负责把代码再翻译一遍。

## 文件头

每个脚本在 `extends` 下一行用 `##` 写三件事：职责、挂载前提、所属章节。正式游戏脚本的章节写「游戏」。

```gdscript
extends Area2D
## 玩家碰到后增加分数，然后消失。
## 挂载：Area2D，需要子节点 CollisionShape2D。
## 章节：ch10
```

## 哪些留给后面的章，哪些要就地注释

`.gd` 里，前面章节还没介绍过的写法，要在旁边用一行 `#` 说明它在做什么。例如三元表达式 `条件 if 真值 else 假值` 没有单独的章节，第一次出现就要注释。已经在前面章节讲过的函数、类型、`if`、`for`，不要再逐行翻译。后面某章才会展开的引擎用法，注释里标明章节即可。

`.tscn` 和 `project.godot` 的存盘格式没有对应章节。中括号标题、`ext_resource`、`ExtResource`、`parent` 这类结构，在文件里用分号注释写明它在连接什么。后面某章会讲的字段不要逐个翻译，只在那一段注明章节，例如锚点留到第 13 章。

这类文件的注释以 `;` 开头，单独占一行。Godot 在编辑器里保存场景时可能丢掉这些分号注释。生成或手改之后若发现注释没了，按本节补回。

## 什么时候写 `#`

- 引擎回调都要在函数体第一行用一句 `#` 写明引擎何时调用它。例如 `_ready` 是进场景树后一次，`_process` 是每帧，`_physics_process` 是每个物理步，`_unhandled_input` 是还有没被吃掉的输入事件时。前面章节讲过这个回调，也要留这句时机，不要只靠函数名。不要把函数体再翻译一遍。
- 节点路径、碰撞层、组名这类场景里的约定，单看脚本看不出来。
- 为了留在本章范围而做的简化，并标明哪一章会再展开。
- 导出变量的单位或取值含义，例如速度是像素/秒。

公开的函数、信号、`@export` 变量用 `##` 写一句说明。

## 推荐

```gdscript
## 水平方向速度，单位是像素/秒。
@export var move_speed: float = 240.0

func _physics_process(delta: float) -> void:
	# 引擎每个物理步调用一次。重力加在这里，避免帧率变化时手感不一样。
	velocity.y += GRAVITY * delta
```

## 避免

- 下一行已经把意思说完的注释，例如在 `velocity = Vector2.ZERO` 上面写「把速度设为零」。
- 大段注释掉的旧实现。不再使用就删掉，需要回忆时看版本记录。
- 同一件事中英各写一遍。
- 没有说明的 `TODO`。要留后续时写成「第 17 章再把分数写入存档」这种能定位的句子。
- 用注释代替坏掉的逻辑。缺节点就 `push_error`。

## 示例 README 里的说明
